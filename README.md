# GutC

Portable C11 foundation for selected GutTS contracts, pinned to `3e2cbc0990ba29830ce91c5d1a1d552675d5334c`.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
cmake --install build --prefix /tmp/gutc
cmake -S tests/consumer -B consumer-build -DCMAKE_PREFIX_PATH=/tmp/gutc
cmake --build consumer-build
```

The pinned cross-language corpus in `testdata/upstream-golden/contracts.tsv` is independently executed by a Node build of the exact GutTS commit and a CTest runner. The install exports `GutC::gutc` from `find_package(GutC CONFIG REQUIRED)`.
Source-derived semantic ranking uses `<gutc/semantic_rank.h>` with stable score sorting and injected MiniLM/Ettin host callbacks. Without genuine model scores it returns `GUTC_UNSUPPORTED`; locale-dependent Unicode tie cases require an ICU adapter. Pinned GutTS OAuth contract primitives are implemented in `<gutc/contract_primitives.h>` as pure, reentrant predicates with 256 UTF-16 code-unit and ECMAScript whitespace rules. These functions validate shapes and identifiers only; they never authorize access. Native Luth client origin normalization, origin fallback and deployment environment classification are exposed by `<gutc/luth_origin.h>`. The native API accepts host-supplied origin values rather than accessing browser globals and deliberately rejects unsupported WHATWG/IDNA cases. All eight pinned model metadata definitions are available through `<gutc/model_registry.h>` with independent owned DOM results. Model API execution still requires a real host adapter. The real native C11 operation dispatcher `gutc_execute_api()` covers the 33 portable utility API identifiers with owned JSON-DOM results and an explicit JavaScript-undefined flag. Five model API identifiers require an injected host callback; they never report success without verified results. Some Unicode, WHATWG URL, formatting and JavaScript-regexp edge cases deliberately return `GUTC_UNSUPPORTED`. The pinned 38-entry GutTS API catalog, by-ID lookup and full FOD metadata catalog are implemented in `<gutc/api_registry.h>` using caller-owned results. The full set includes model descriptors **but does not pretend to execute model inference**. Source-derived FOD node metadata adaptation is exposed via `<gutc/fod_node.h>`, returning an independently owned JSON DOM. Deterministic schema-based semantic input resolution is exposed via `<gutc/semantic_deterministic.h>`; it does not run models, rank candidates or pretend to support JavaScript regular expressions. Source-derived `defineApi` input-schema metadata generation is available via `<gutc/api_definition.h>` and returns an owned JSON DOM. Owned JSON deep-path pick/omit and path-existence checks are available via `<gutc/object_path.h>`, with the same explicit ownership/free contract as JSON DOM. ASCII-scoped Lodash case transforms and email validation are available via `<gutc/string_case.h>`; non-ASCII inputs fail with `GUTC_UNSUPPORTED` rather than corrupting Unicode. Portable OAuth client and redirect contract shape validators are exposed via `<gutc/oauth_contracts.h>` (not proof of ownership). Pure versioned capability and scoped invocation shape/budget validators are exposed from `<gutc/auth_contracts.h>`, with exact reason strings. These never replace target-side authorization. HTTP(S) URL search parameter get/set and form encoding are available via `<gutc/url_query.h>` with explicit non-WHATWG host exceptions. Heap-owned structured JSON parsing and serialization are available via `<gutc/json_dom.h>`, with bounded node/depth budgets and `gutc_json_dom_free()`. Borrowed primitive/reference collections and ordered-map direct key selection are exposed via `<gutc/collections.h>`. JSON syntax validation and UTF-8 string quoting are exposed via `#include <gutc/json.h>`. The core byte-span API is allocation-free and reentrant (imported path normalization allocates temporary memory); see `include/gutc/gutc.h` for buffer ownership and status handling. Safe storage-relative URI encoding and borrowed identity/legacy mapping are also available via `<gutc/safe_path.h>` and `<gutc/identity.h>`. Existing URL security and Unicode helper implementations from PRs #1, #3, and #4 are integrated. The library is **not yet fully parity-certified**; see `docs/upstream-parity.md` and the existing open GutC PRs.
